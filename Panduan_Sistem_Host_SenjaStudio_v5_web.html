1Gambaran Umum

Sistem internal Senja Studio untuk mengelola host live streaming, terdiri dari dua sistem yang saling melengkapi:

1. Sistem Evaluasi — coaching & penilaian

Leader menilai host (17 poin / 6 kategori), set target; host menerima email notifikasi & melihat progress skornya. Untuk pengembangan kualitas host.

2. Sistem Performa Live — data penjualan (TikTok & Shopee)

Host mengisi data tiap sesi live (GMV, viewers, dll) di TikTok atau Shopee; sistem menghitung metrik konversi otomatis. Leader memantau performa semua host, bisa import data export TikTok/Shopee, beralih antara tampilan TikTok / Shopee / Gabungan, dan membandingkan bulan-ke-bulan langsung dari Beranda.

2Peta Halaman & Login Terpusat

Sistem terdiri dari 4 halaman. Login hanya dilakukan satu kali di halaman Beranda (performa) — halaman lain otomatis terbuka tanpa login ulang karena berbagi sesi yang sama.

HalamanLinkUntukFungsi

Dashboard Evaluasitinyurl.com/dashboard-senjaLeaderPantau skor semua host, export PDF

Cara kerja login terpusat

Buka Beranda (performa-senja) → login sekali pakai email & password. Dari Beranda, semua menu bisa diakses tanpa login ulang. Kalau ada yang buka link halaman lain langsung tanpa login, otomatis diarahkan kembali ke Beranda.

Beranda berbeda untuk leader, host & viewer

Host melihat GMV bulan terpilih + menu (Input Performa, Performa Saya, Hasil Evaluasi). Untuk host multi-brand, GMV di Beranda adalah gabungan semua brand-nya. Leader melihat total GMV tim + menu (Input Evaluasi, Dashboard Evaluasi, Dashboard Performa, Import Data).

Viewer / HRD (read-only) melihat tampilan seperti leader untuk Performa saja: Beranda (Total GMV tim), Dashboard Performa, Banding, Tren — lengkap dengan toggle platform. Yang disembunyikan: Import Data, Input/Dashboard Evaluasi, serta tombol Edit & Hapus. Header bertuliskan "Panel HRD". Murni memantau, tidak bisa mengubah data.

Beranda: pilih bulan & banding bulan-ke-bulan V4

Di samping toggle platform ada dropdown bulan (host & leader). Bulan berjalan bertanda "(berjalan)". Ganti bulan → hero, badge, statistik, dan kartu brand ikut berubah. Di samping angka GMV ada chip persentase naik/turun dibanding bulan sebelumnya, plus badge ▲▼ kecil pada sesi, pembeli, viewers, dan tiap kartu brand (leader). Hero juga menampilkan sparkline GMV harian — arahkan kursor untuk melihat angka per tanggal.

Menu Analisis Leader

Panel leader punya dua tab analisis: Bandingkan Host (adu metrik antar host dalam satu brand) dan Tren Brand (naik/turun tiap metrik per brand dari bulan ke bulan). Keduanya punya toggle platform (TikTok / Shopee / Gabungan). Patokan "siapa lebih jago" pakai metrik kualitas (AOV/CTOR/CTR atau Klik-Viewer/Engagement), bukan GMV mentah yang dipengaruhi jam tayang.

Cara hitung % perubahan (pacing / MTD)

V5: aturan "periode sama" hanya berlaku untuk bulan berjalan. Bila bulan yang dilihat sudah lewat (data lengkap), pembandingnya bulan penuh vs bulan penuh — misalnya Juni (30 hari) dibanding Mei (31 hari), tanggal 31 Mei tetap ikut dihitung. Sebelumnya Mei ikut terpotong di tanggal 30. Label di layar menyesuaikan: "dibandingkan bulan penuh" atau "dibandingkan sama-sama N hari pertama".

Semua badge perubahan — termasuk chip di Beranda v4 — membandingkan periode yang SAMA: bulan berjalan vs bulan sebelumnya pada rentang hari yang sama (mis. 1–18 vs 1–18), cutoff = tanggal data terakhir. Kalau bulan yang dipilih sudah komplit, pembandingnya bulan penuh vs bulan penuh. Catatan kecil di hero menjelaskan rentang pembandingnya. Di chart Tren, titik bulan berjalan ditandai garis putus-putus (belum lengkap).

Badge perkembangan host

Di Dashboard Performa, tiap kartu host menampilkan badge naik/turun (hijau ▲ / merah ▼) dibanding bulan lalu — pada GMV, viewers, dan metrik kualitas (AOV, CTR/Klik-Vw, CTOR, Engagement). Di halaman detail host (klik kartu), badge muncul di semua kartu metrik. Untuk menilai perkembangan skill host, utamakan metrik kualitas; badge pada metrik volume (viewers, likes) lebih dipengaruhi jam tayang & jumlah sesi.

3Setup Database (Supabase)

Sistem memakai 4 tabel: evaluasi_host (penilaian), live_performance (data sesi live), app_config (tim & brand) dan host_libur (libur), plus 1 view host_perf_bulanan untuk cokesir.love (3.9). Semua perintah dijalankan di menu SQL Editor. Tidak ada perubahan skema di v4.

3.1 Buat Project

Daftar di supabase.com → New Project → region Asia Pacific (Singapore) → centang Enable Data API.

Kalau opsi automatic RLS ikut dicentang, Supabase sendiri membuat function rls_auto_enable + event trigger ensure_rls (RLS otomatis aktif di tiap tabel baru). Itu bawaan Supabase, bukan dari panduan ini — biarkan saja.

3.2 Tabel Evaluasi

create table evaluasi_host (
  id bigint primary key generated always as identity,
  host text, brand text, host_email text,
  evaluasi_ke text, tanggal date,
  commitment text, target text,
  target_acknowledged boolean default false,
  total int, max int, avg numeric,
  filled_count int, sections jsonb,
  created_at timestamptz default now()
);

3.3 Tabel Performa Live (TikTok & Shopee)

Satu tabel untuk dua platform (kolom platform = 'tiktok'/'shopee', atc khusus Shopee). Kolom brand disimpan per baris, jadi satu host bisa punya data di beberapa brand tanpa perubahan skema.

create table live_performance (
  id bigint primary key generated always as identity,
  host text, brand text, host_email text,
  tanggal date, sesi int,
  platform text default 'tiktok',  -- 'tiktok' / 'shopee'
  gmv numeric, pembeli int, items int,
  viewers int, impresi int, klik_produk int,
  atc int default 0,               -- Add to Cart (khusus Shopee)
  avg_view_dur numeric, durasi_menit numeric,
  followers_baru int, likes int, komentar int,
  screenshot_url text,
  created_at timestamptz default now()
);

Kolom sections (jsonb) di tabel evaluasi: semua skor per kategori dikemas jadi satu paket JSON — menambah/mengubah kategori tidak perlu mengubah struktur tabel, cukup edit file HTML.

3.4 Aktifkan Keamanan (RLS) — kedua tabel

Jalankan untuk tiap tabel (evaluasi_host dan live_performance). Contoh untuk live_performance:

alter table live_performance enable row level security;
grant all on table live_performance to anon;
grant all on table live_performance to authenticated;

create policy "host lihat performa sendiri" on live_performance
  for select using (host_email = auth.jwt() ->> 'email');
create policy "host input performa sendiri" on live_performance
  for insert with check (host_email = auth.jwt() ->> 'email');
create policy "host edit performa sendiri" on live_performance
  for update using (host_email = auth.jwt() ->> 'email')
  with check (host_email = auth.jwt() ->> 'email');
create policy "leader akses semua performa" on live_performance
  for all using (auth.jwt() ->> 'email' = 'fajarzinfo@gmail.com');

Viewer / HRD (read-only) — aktif di database: policy for select saja, tanpa insert/update/delete. Ganti EMAIL_HRD dengan email di VIEWER_EMAILS:

create policy "hrd lihat semua performa" on live_performance
  for select using (auth.jwt() ->> 'email' = 'EMAIL_HRD');

Untuk tabel evaluasi_host, polanya mirip tapi tidak sama persis — yang meng-input evaluasi adalah leader (bukan host), dan host butuh izin update di barisnya sendiri supaya tombol konfirmasi target ("✓ Saya mengerti") di host.html berfungsi:

alter table evaluasi_host enable row level security;
grant all on table evaluasi_host to anon;
grant all on table evaluasi_host to authenticated;

create policy "host lihat data sendiri" on evaluasi_host
  for select using (host_email = auth.jwt() ->> 'email');
create policy "host konfirmasi target" on evaluasi_host
  for update using (host_email = auth.jwt() ->> 'email')
  with check (host_email = auth.jwt() ->> 'email');
create policy "leader bisa semua" on evaluasi_host
  for all using (auth.jwt() ->> 'email' = 'fajarzinfo@gmail.com');

3.5 Ambil Credentials

Settings → API Keys. Copy Project URL dan anon public key (dipakai di semua file HTML). Project URL selalu https://[PROJECT_ID].supabase.co. Jangan pakai service_role / secret key — selalu anon public key; keamanan dijaga RLS.

3.6 Setup Storage (Screenshot Dashboard)

Host bisa melampirkan screenshot tiap sesi (klik, drag, atau tempel Ctrl+V). Storage → New bucket → nama screenshots → Public bucket: ON → Save. Lalu beri izin upload:

create policy "host upload screenshot"
  on storage.objects for insert to authenticated
  with check (bucket_id = 'screenshots');

Bucket wajib Public (kode pakai getPublicUrl). Gambar otomatis dikompres (maks 1280px, JPEG) — hemat kuota (Storage free 1 GB).

3.8 Tabel Libur Host (host_libur) V5

Menyimpan tanggal libur tiap host — dipakai tab Libur & Kelengkapan Data (bab 8) dan tampil sebagai baris "(libur)" di riwayat sesi. Jalankan sekali:

create table host_libur (
  id uuid primary key default gen_random_uuid(),
  host_email text not null,
  tanggal date not null,
  keterangan text,
  created_at timestamptz default now(),
  unique (host_email, tanggal)
);
alter table host_libur enable row level security;
grant usage on schema public to authenticated;
grant all on table public.host_libur to authenticated;
grant all on table public.host_libur to service_role;
create policy "leader akses semua libur" on host_libur
  for all using (auth.jwt() ->> 'email' = 'fajarzinfo@gmail.com');
create policy "host lihat libur sendiri" on host_libur
  for select using (auth.jwt() ->> 'email' = host_email);
-- HRD (read-only) — aktif di database; ganti EMAIL_HRD:
create policy "hrd lihat semua libur" on host_libur
  for select using (auth.jwt() ->> 'email' = 'EMAIL_HRD');

Penting: baris grant wajib ikut dijalankan. Tanpa itu muncul error permission denied for table host_libur saat menandai libur — itu error izin table-level, beda dari error RLS (violates row-level security policy) yang berarti email di policy tidak cocok dengan email login.

unique (host_email, tanggal) mencegah satu host ditandai libur dua kali di tanggal sama. Aplikasi juga menolak menandai libur bila host sudah punya data sesi di tanggal itu.

3.9 Rekap Bulanan untuk cokesir.love (host_perf_bulanan)

Menu Performance → Hosts di cokesir.love menampilkan data performa live dari Supabase ini, read-only. Semua input tetap lewat sistem ini (GitHub Pages); cokesir hanya membaca. Server cokesir login sebagai akun khusus cokesir@senja.local lalu membaca view di bawah. Jalankan sekali:

-- rekap per bulan x host x brand x platform; RLS live_performance tetap berlaku (security_invoker)
create or replace view public.host_perf_bulanan with (security_invoker = true) as
select
  to_char(tanggal, 'YYYY-MM')            as bulan,
  host_email,
  max(host)                              as host,
  brand,
  coalesce(platform, 'tiktok')           as platform,
  count(*)::int                          as sesi,
  coalesce(sum(durasi_menit), 0)::int    as durasi_menit,
  coalesce(sum(gmv), 0)                  as gmv,
  coalesce(sum(pembeli), 0)::int         as pembeli,
  coalesce(sum(followers_baru), 0)::int  as followers_baru,
  min(tanggal)                           as tanggal_awal,
  max(tanggal)                           as tanggal_akhir,
  count(distinct tanggal)::int           as hari,
  coalesce(sum(items), 0)::int           as items,
  coalesce(sum(viewers), 0)::int         as viewers
from live_performance
group by 1, 2, 4, 5;

revoke all on public.host_perf_bulanan from anon;
grant select on public.host_perf_bulanan to authenticated;

create policy "cokesir baca performa" on live_performance
  for select using (auth.jwt() ->> 'email' = 'cokesir@senja.local');

Lalu buat akunnya: Authentication → Users → Add user → email cokesir@senja.local, password kuat, centang Auto Confirm User. Password hanya disimpan di server cokesir (/etc/senja/runtime.env), jangan ditulis di panduan atau repo.

Di server cokesir (/opt/senja, dikerjakan lewat Codex, bukan git) ada 4 env di /etc/senja/runtime.env: SENJA_SUPABASE_URL, SENJA_SUPABASE_ANON_KEY, SENJA_READER_EMAIL, SENJA_READER_PASSWORD. Tampilan dibuat di app/app/host-performance-senja.tsx, data lewat app/api/staff-performance/senja + lib/senja.ts.

Rollback ke versi TikTok API bos: di app/app/tool-app.tsx ganti <HostPerformanceSenja …/> kembali ke <StaffPerformancePanel type="hosts" …/> lalu build + restart senja.service (kode lama tidak dihapus). Cadangan: build asli /opt/senja-dist-sebelum-host-perf-senja.tgz dan source asli /opt/senja-backup-host-perf-20260922-125612.tar.gz.

Kalau kolom baru ditambahkan ke view: tambahkan di akhir daftar kolom (create or replace view tidak bisa mengubah urutan/menghapus kolom lama).

7Sistem Performa Live (TikTok & Shopee)

Host mengisi data tiap sesi live. Ada 4 sesi utama; host boleh isi sesi sama berkali-kali (mis. live ulang karena error).

SesiJamSesiJam

Pilih Brand & Platform dulu

Di form Input Performa, urutan dropdown paling atas:

  • Brand — muncul hanya untuk host yang pegang lebih dari satu brand; host pilih sesi ini untuk brand apa. Host satu brand tidak melihat dropdown ini (brand otomatis).
  • Platform — TikTok (default, ada field Impresi) atau Shopee (Impresi dibuang, muncul field ATC / Add to Cart).

Data yang Diisi Host (per sesi)

Dropdown: Brand (jika multi-brand), Platform, Tanggal, Sesi. Angka mentah: GMV, Pembeli, Items Sold, Viewers, Klik Produk, Avg View Duration (dtk), Followers Baru, Likes, Komentar, Durasi. Lalu Impresi (TikTok) atau ATC (Shopee). Untuk Shopee, angka dibaca dari halaman Data Insight per-live (GMV = Sales Confirmed Order, Pembeli = Buyers, Klik = Product Clicks).

Field angka menerima titik sebagai pemisah ribuan. Mengetik 410.256 maupun 410256 sama-sama benar (410.256), dan otomatis terformat saat diketik. Avg View Duration tetap boleh desimal dengan titik, mis. 19.5 detik.

Form Evaluasi Host & Draft V5

Di evaluasi_host_live.html, form sekarang langsung pilih host — tidak lagi pilih brand dulu. Alasannya evaluasi menilai hostnya, bukan brandnya; host yang memegang dua brand tetap dinilai sama. Kolom brand di database tetap terisi otomatis (brand pertama host di app_config) supaya filter rekap di Dashboard Evaluasi tetap jalan.

TombolEfek
Simpan & kirim emailLangsung masuk database + email notifikasi terkirim ke host saat itu juga (perilaku lama).
Jadikan draftDisimpan sementara di perangkat. Belum masuk database, belum kirim email — host & HRD belum melihat apa pun.

Panel Draft evaluasi muncul di atas Riwayat: daftar semua draft (host, skor, tanggal), bisa di-Edit (dimuat kembali ke form) atau dihapus. Tombol Publish semua menyimpan seluruh draft ke database satu per satu sekaligus mengirim emailnya, dengan progres per host. Bila ada yang gagal, draft itu tidak hilang dan bisa dicoba lagi.

Alur yang dituju: nilai semua host, simpan masing-masing sebagai draft, review, lalu publish serentak — supaya semua host menerima email di waktu yang sama, bukan bertahap.

Catatan: draft disimpan di localStorage perangkat yang dipakai — draft yang dibuat di HP tidak muncul di laptop, dan hilang bila data browser dibersihkan. Cocok untuk satu leader satu perangkat. Bila nanti perlu draft yang sinkron antar perangkat, tambahkan kolom status di evaluasi_host lalu filter status = 'published' di dashboard.html dan host.html.

8Libur & Kelengkapan Data V5

Tab Libur & Data di panel leader (HRD bisa lihat, read-only). Gunanya memisahkan dua hal yang tampak sama di data kosong: host yang memang libur vs host yang lupa mengisi performanya.

Menandai host libur

Pilih host, tanggal (default besok), keterangan opsional, lalu Tandai libur. Efeknya dua:

  • Di riwayat sesi host (drilldown leader & "Performa Saya" milik host), tanggal itu muncul sebagai baris redup 15 Jun (libur) dengan data "—".
  • Di kelengkapan data, tanggal itu dihitung beres — tidak masuk daftar "belum diisi".

Baris libur murni penanda: tidak ikut dihitung di GMV, rata-rata, chart, maupun metrik konversi apa pun. Leader bisa menghapus tanda libur dari tab ini atau langsung dari baris di riwayat sesi.

Host lihat kelengkapannya sendiri

Di beranda host juga muncul kartu status untuk bulan yang sedang dipilih, dengan baris terpisah untuk TikTok dan Shopee. Tujuannya host sadar dan menyusul sendiri tanpa perlu ditagih. Perhitungannya sama dengan sisi leader (bulan berjalan dicek sampai hari ini), dan tidak terpengaruh toggle TikTok/Shopee di layar — kedua platform selalu ditampilkan sekaligus.

Cek kelengkapan akhir bulan (leader)

Pilih bulan, lalu tiap host aktif menampilkan status terpisah per platform — karena setiap host mengisi data di TikTok dan Shopee, satu tanggal baru dianggap beres bila kedua platform terisi. Tiap baris berisi Lengkap, atau N belum diisi beserta daftar tanggalnya; hari libur dicatat di bawahnya. Contoh: Nadya bisa Lengkap di TikTok tapi kurang tanggal 15 di Shopee. Aturan periode:

  • Bulan berjalan — dicek hanya sampai hari ini, supaya tanggal yang belum lewat tidak terhitung bolong.
  • Bulan yang sudah lewat — dicek satu bulan penuh.

Daftar libur di bawahnya dikelompokkan per host dengan tanggal terurut, bukan urutan input.

Alur akhir bulan: buka tab Libur & Data, pilih bulan yang baru selesai, host yang masih bertanda peringatan berarti benar-benar ada tanggal yang belum diisi — tinggal ditagih ke hostnya. Yang libur sudah otomatis bersih.

Metrik Dihitung Otomatis — per Platform

MetrikRumusTikTokShopee
AOVGMV ÷ Pembeli✓✓
CTORPembeli ÷ Klik✓✓
GMV / JamGMV ÷ (durasi/60)✓✓
Engagement(Likes+Komentar) ÷ Viewers✓✓
CTRKlik ÷ Impresi✓✗
GPMGMV ÷ Impresi × 1000✓✗

"Klik/Viewer" bukan "CTR". CTR sejati = Klik ÷ Impresi. Shopee per-live tidak menyediakan Impresi, jadi dipakai Klik/Viewer dan tidak dilabeli CTR. Host tidak pernah mengetik metrik persen — semuanya dihitung otomatis dari angka mentah.

Toggle TikTok / Shopee / Gabungan

Tombol toggle muncul di semua layar performa (Beranda, Dashboard, Banding, Tren, Performa Saya). TikTok/Shopee menyaring per platform & menampilkan metrik sesuai platform. Gabungan menjumlah GMV + volume (sesi, pembeli, items, viewers) + AOV dua platform; rasio funnel tidak dicampur. Tabel Riwayat Sesi punya kolom Plat agar tiap baris terbedakan.

Performa Saya per brand

Host multi-brand punya filter brand di "Performa Saya" — metrik ditampilkan per brand supaya rasio funnel (CTR/CTOR/Engagement) tidak tercampur antar brand. Host satu brand tidak melihat filter ini.

Kenapa isi angka mentah, bukan rate jadi?

Dengan angka mentah, leader bisa diagnosa di tahap mana host "bocor" — traffic kurang (viewers), konten kurang menarik (CTR/Klik-Viewer), atau closing lemah (CTOR). Ini bikin coaching lebih tajam.

Edit & Koreksi Riwayat Sesi

Salah input tidak perlu dihapus — tiap baris bisa dikoreksi via Edit (host hanya baris miliknya; modal Edit ikut platform & ATC). Brand juga bisa diganti dari modal Edit V5 — dropdown brand hanya muncul bila host pemilik sesi memegang lebih dari satu brand, jadi salah pilih brand tidak perlu input ulang. Semua rekap dihitung ulang otomatis dari data terkoreksi (tidak ada agregat tersimpan), termasuk banding bulan-ke-bulan bila sesi yang dipindah ada di bulan pembanding. Hapus hanya untuk leader (permanen). Tabel riwayat yang panjang di-scroll di dalam area sendiri dengan header yang tetap terlihat V4.

9Import Data (TikTok & Shopee)

Langkah Import

Login leader → Beranda → Import Data → pilih brand file (Onebear / Supoe / Momso) → assign host Sesi 1&2 (pagi–siang) dan Sesi 3&4 (sore–malam) → upload/drag file. Hindari import dobel (menggandakan data). File overview-v2…csv (rekap bulanan) bukan data per-live dan ditolak otomatis. Tidak perlu pilih bulan — sistem membaca tanggal asli tiap baris.

Catatan teknis — perilaku sistem

  • Data tidak terpotong di 1.000 baris. Sistem memuat data bertahap (paginasi) sampai habis — aman untuk data bertahun-tahun.
  • Filter Dashboard menetap. Pilihan brand + bulan di Dashboard Performa tidak ter-reset saat membuka detail host; bulan diwarisi ke tampilan detail. Default awal = bulan terbaru yang ada datanya.
  • Pilihan bulan Beranda menetap (v4) — tidak ter-reset saat ganti platform atau pindah tab, kembali ke bulan berjalan saat halaman di-refresh.
  • Total GMV per host tetap utuh walau host pegang 2 brand: Beranda host = gabungan; Dashboard leader filter "Semua brand" = total lintas brand; pilih satu brand = terpisah.
  • Default host pagi/sore saat import (bisa diganti manual): Onebear → Sinta/Indah · Supoe → Nadya/Salma · Momso → Yaya/Fira.

Catatan: Layanan yang Sempat Dicoba

  • Netlify (hosting) — diganti GitHub Pages. Free plan Netlify hanya 300 credits/bulan & tiap deploy makan 15 credits, cepat habis. GitHub Pages gratis tanpa batas deploy.
  • Resend (email) — diganti EmailJS. Free plan Resend (domain resend.dev) hanya bisa kirim ke email pemilik akun sendiri. EmailJS bisa kirim ke email manapun via Gmail biasa, tanpa perlu domain.
Penting untuk rebuild dari nol: panduan ini berisi semua skrip infrastruktur (SQL tabel, migrasi, RLS kedua tabel, storage, config yang diedit) — tapi kode aplikasinya hidup di 9 file repo, bukan di panduan. Panduan ini sengaja tidak ditaruh di repo — isinya email tim dan detail server cokesir, sedangkan repo-nya publik. Akibatnya keduanya punya risiko berbeda: kode aman selama repo GitHub ada, tapi panduan ini cuma ada di komputer leader. Jadi simpan panduan (atau PDF-nya) di tempat kedua — Google Drive, email ke diri sendiri, atau flashdisk — dan sesekali download zip repo (tombol Code → Download ZIP) lalu simpan berdampingan. Panduan + 9 file = sistem lengkap; salah satu saja tidak cukup.

Untuk modifikasi, gunakan Claude AI dengan melampirkan file terkait (lihat bagian 11).
